# German learning API

## Датасеты слов

Датасет объединяет слова из выбранных тегов и отдельные слова пользователя. Создайте его через `POST /api/datasets/`, передав `name`, массивы ID `tags` и `extra_words` (здесь нужны ID `UserWord` из `GET /api/words/me`). Обновить состав можно через `PATCH /api/datasets/{dataset_id}`. Запрос `GET /api/datasets/{dataset_id}/words` показывает текущий набор слов без повторов.

Связь с тегом хранится в датасете, поэтому слова, добавленные в этот тег позже, автоматически попадут в набор. Отдельное слово останется в наборе, даже если оно не входит ни в один выбранный тег. Несколько расписаний могут использовать один датасет; изменение его состава влияет на их будущие запуски. И API датасетов, и `/api/words/me` доступны с пользовательским токеном или авторизацией Telegram-бота (`X-API-Key` и `X-Telegram-ID`). Сервер проверяет принадлежность тегов и отдельных слов пользователю.

При создании расписания через `POST /api/schedules/` передайте `dataset_id` вместо прежнего массива `tags`; его можно сменить через `PATCH /api/schedules/{schedule_id}`. Значение `null` означает «Все мои слова». Планировщик выбирает только слова со статусом `learning`. При создании расписания, в том числе выключенного, доступных слов должно быть не меньше `items_per_delivery`. Если позже доступных слов станет меньше, текущий слот пропускается, а следующий срок рассчитывается по расписанию. Когда слов достаточно, выборка сначала берёт ни разу не показанные слова, затем показанные раньше, но не сегодня, и при необходимости добирает сегодняшними повторами. Датасет, на который ссылается расписание, удалить нельзя.

При миграции для каждого старого расписания с тегами создаётся отдельный датасет `Расписание #<id>` с теми же тегами. Старые расписания без тегов сохраняют прежнее значение «все изучаемые слова» с `dataset_id: null`. В новых запросах поле `dataset_id` обязательно, но тоже может быть `null`.

## Фоновые запуски расписаний

Celery Beat раз в минуту запускает `dispatch_due_schedules`. Эта задача находит активные расписания, у которых наступило `next_run_at`, и ставит в очередь `process_due_schedule` для каждого из них. Worker создаёт `ScheduleRun` с выбранными словами и рассчитывает следующий срок. Если задача окажется в очереди дважды, проверка и блокировка строки расписания не дадут создать второй запуск.

Для локального запуска нужен Redis. На Windows запускайте Celery в WSL или Docker: Windows официально не поддерживается Celery.

```bash
docker run --name german-redis -p 6379:6379 -d redis:7
uv sync
```

Укажите `CELERY_BROKER_URL` в `.env`, если Redis находится не на `localhost:6379`. Из каталога `german_learning_api` запустите два отдельных процесса:

```bash
uv run celery -A german_learning_api worker --loglevel=info
uv run celery -A german_learning_api beat --loglevel=info
```

Запускайте только один экземпляр Beat. Созданные запуски пока остаются в статусе `pending`: канал доставки слов пользователю ещё не подключён.

Beat создаёт рядом с собой служебный файл `celerybeat-schedule` (иногда с дополнительным расширением). Это файл состояния самого Beat, поэтому он указан в `.gitignore`.
