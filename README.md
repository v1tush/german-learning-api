# German learning API

## Привязка Telegram

Вошедший на сайт пользователь вызывает `POST /api/users/me/telegram-link` с access-токеном. Ответ содержит одноразовый `token` и `expires_at` (через 10 минут). Повторный запрос выдаёт новый токен и отменяет предыдущий. Сайт может передать токен боту через ссылку вида `https://t.me/<bot_username>?start=<token>`; сам бот пока не реализован.

Получив `/start <token>` в личном чате, будущий бот должен вызвать `POST /api/users/telegram-link/confirm` с JSON `{"token": "..."}` и заголовками `X-API-Key` (служебный ключ бота) и `X-Telegram-ID` (ID отправителя сообщения Telegram). Только этот запрос записывает `telegram_id` в профиль пользователя; сайт не может указать произвольный ID. Токен одноразовый, просроченный или занятый другим пользователем Telegram ID не привязывается. После привязки существующий `BotAuth` узнаёт пользователя по `X-Telegram-ID`; текущее значение видно через `GET /api/users/me/`.

## Переводы и формы слов

При сравнении нового перевода с сохранёнными вариантами текст приводится к Unicode NFC, регистр игнорируется, а последовательности пробельных символов считаются одним пробелом. Исходный текст уже сохранённого варианта при совпадении остаётся прежним.

Для общего перевода на текущий язык пользователя нужен непустой `is_main`. `GET /api/translations/words/{word_id}/translations` только показывает сохранённые варианты. `POST /api/translations/words/{word_id}/translation-suggestions` возвращает варианты сразу, если главный перевод уже есть; иначе запрашивает AI, сохраняет варианты и назначает главный. Наличие одних только вариантов с `is_main=false` больше не останавливает генерацию. Если AI не нашёл перевод, ответ сохраняет ранее известные варианты с `is_main=false`. Карточка использует непустой `custom_translation`, затем выбранный пользователем перевод для текущего языка, затем `is_main`. `POST /api/schedules/{schedule_id}/cards/{user_word_id}/resolve-answer` обращается к той же логике сохранения главного перевода, только если у карточки нет ответа.

Для форм слова доступны `GET` и `POST /api/words/{word_id}/inflections`, а также `GET`, `PATCH` и `DELETE /api/words/{word_id}/inflections/{inflection_id}`. При создании передайте `type` (например, `de_partizip_2`) и непустое `value`; изменение формы допускает оба поля. На одно слово разрешена одна форма каждого типа. Обычный пользователь может читать формы слова из своего словаря; только активный пользователь с `is_staff=true` может добавлять, изменять и удалять формы любого слова. Это правило действует и для запросов Telegram-бота. API проверяет соответствие типа языку и части речи. `WordInflection` привязана к общему `Word`, поэтому изменение формы видно всем пользователям с этим словом.

Формы можно импортировать из [UniMorph/deu](https://github.com/unimorph/deu) (источник: English Wiktionary, лицензия CC BY-SA 3.0). Команда берёт закреплённую версию файла `deu` и извлекает `de_partizip_2`, `de_prateritum` и `de_plural`. По умолчанию она только показывает план; `--apply` записывает данные. `--scope existing` дополняет уже заведённые немецкие `Word`, а `--scope all` создаёт также новые слова для найденных однозначных форм. Существующие формы не перезаписываются; случаи с несколькими вариантами пропускаются и доступны в TSV-отчёте через `--report`. AI для импорта форм не используется.

```bash
cd german_learning_api
uv run python manage.py import_unimorph_de --scope all --report unimorph-report.tsv
uv run python manage.py import_unimorph_de --scope all --apply --report unimorph-report.tsv
```

Для импорта заранее скачанного файла добавьте `--file /path/to/deu`. Полный импорт создаёт десятки тысяч глобальных `Word`.

Глобальный каталог слов отдаётся через `GET /api/words/pages/{sort}/{page}`. Оба параметра обязательны в пути: `sort` — `id` (возрастание ID) или `popular` (убывание текущего количества пользователей, добавивших слово, при равенстве — возрастание ID), `page` — номер страницы от 1. Например, `/api/words/pages/popular/2` возвращает вторую сотню. Ответ содержит `words` (не более 100), `page`, `sort`, `page_size: 100` и `has_next`; пустая страница возвращает пустой массив. Старый `GET /api/words` удалён.

## Датасеты слов

Датасет объединяет слова из выбранных тегов и отдельные слова пользователя. Создайте его через `POST /api/datasets/`, передав `name`, массивы ID `tags` и `extra_words` (здесь нужны ID `UserWord` из `GET /api/words/me`). Обновить состав можно через `PATCH /api/datasets/{dataset_id}`. Запрос `GET /api/datasets/{dataset_id}/words` показывает текущий набор слов без повторов.

Связь с тегом хранится в датасете, поэтому слова, добавленные в этот тег позже, автоматически попадут в набор. Отдельное слово останется в наборе, даже если оно не входит ни в один выбранный тег. Несколько расписаний могут использовать один датасет; изменение его состава влияет на их будущие запуски. И API датасетов, и `/api/words/me` доступны с пользовательским токеном или авторизацией Telegram-бота (`X-API-Key` и `X-Telegram-ID`). Сервер проверяет принадлежность тегов и отдельных слов пользователю.

При создании расписания через `POST /api/schedules/` передайте `dataset_id` вместо прежнего массива `tags`; его можно сменить через `PATCH /api/schedules/{schedule_id}`. Значение `null` означает «Все мои слова». Поле `mode` задаёт время запуска (`interval` или `fixed_times`), а `exercise_kind` — тип упражнения (`translation` или `inflection`). Для `inflection` обязательно укажите `inflection_type`, например `de_partizip_2`; для `translation` оно должно быть `null`. Планировщик выбирает только слова со статусом `learning`, а для форм — только слова с заполненной формой нужного типа. При создании расписания, в том числе выключенного, подходящих слов должно быть не меньше `items_per_delivery`. Если позже их станет меньше, текущий слот пропускается, а следующий срок рассчитывается по расписанию. Когда слов достаточно, выборка сначала берёт ни разу не показанные в этом типе упражнения слова, затем показанные раньше, но не сегодня, и при необходимости добирает сегодняшними повторами. Датасет, на который ссылается расписание, удалить нельзя.

При миграции для каждого старого расписания с тегами создаётся отдельный датасет `Расписание #<id>` с теми же тегами. Старые расписания без тегов сохраняют прежнее значение «все изучаемые слова» с `dataset_id: null`. В новых запросах поле `dataset_id` обязательно, но тоже может быть `null`.

## Напоминания на сайте и карточки

Каждый запуск расписания создаёт одно уведомление для сайта. Фронтенд может раз в минуту опрашивать `GET /api/notifications/`: по умолчанию ответ содержит только непрочитанные уведомления; `?unread_only=false` возвращает и прочитанные. `POST /api/notifications/{notification_id}/read` помечает уведомление прочитанным. Это не отключает расписание и не сдвигает `next_run_at`. Уведомление содержит `schedule_id` и `dataset_id`, чтобы открыть повторение.

`GET /api/schedules/{schedule_id}/cards` возвращает все слова текущего датасета вместе со статусами, ответами и источниками ответов. Если `dataset_id: null`, возвращаются все слова пользователя. Для режима Quizlet фронтенд выбирает из ответа слова со статусом `learning`, перемешивает их и показывает карточки. В режиме `inflection` ответом служит форма `inflection_type`; если формы нет, `answer` равен `null`, и фронтенд может исключить карточку. Порядок для перевода: непустой `custom_translation`, затем выбранный пользователем перевод для текущего языка, затем `is_main`. Если перевода нет, `answer` равен `null`; `POST /api/schedules/{schedule_id}/cards/{user_word_id}/resolve-answer` запрашивает перевод у AI для этой карточки, сохраняет варианты в БД и возвращает карточку с ответом. Список карточек сам не запускает массовую генерацию переводов.

## Фоновые запуски расписаний

Celery Beat раз в минуту запускает `dispatch_due_schedules`. Эта задача находит активные расписания, у которых наступило `next_run_at`, и ставит в очередь `process_due_schedule` для каждого из них. Worker создаёт `ScheduleRun` с выбранными словами и рассчитывает следующий срок. Если задача окажется в очереди дважды, проверка и блокировка строки расписания не дадут создать второй запуск.

Для локального запуска нужен Redis. На Windows запускайте Celery в WSL или Docker: Windows официально не поддерживается Celery.

```bash
docker run --name german-redis -p 6379:6379 -d redis:7
uv sync
```

Укажите `CELERY_BROKER_URL` в `.env`, если Redis находится не на `localhost:6379`. Из каталога `german_learning_api` запустите два отдельных процесса:

```bash
uv run celery -A german_learning_api worker --loglevel=info
uv run celery -A german_learning_api beat --loglevel=info
```

Запускайте только один экземпляр Beat. Worker сохраняет запуск и уведомление сайта в одной транзакции. Доставка слов через Telegram пока не подключена.

Beat создаёт рядом с собой служебный файл `celerybeat-schedule` (иногда с дополнительным расширением). Это файл состояния самого Beat, поэтому он указан в `.gitignore`.
